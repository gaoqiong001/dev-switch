# Dev Switch v0.2.0

> **Headline upgrade: migration to Tauri v2**, which makes the silent auto-update genuinely work end-to-end. The signing and release pipeline was reworked to match cc-switch: CI now signs the `.msi` directly (producing `.msi.sig`), and `latest.json` points at the signed `.msi` — so in-app "check for updates / auto-install" finally validates and installs real releases.

## What Changed

- **Migrated to Tauri v2**: backend upgraded from Tauri v1.8.3 to v2.8.0 (the same foundation as the reference app cc-switch); config rewritten to the v2 schema (`app` / `bundle.createUpdaterArtifacts` / `plugins.updater`); added a `capabilities/` permission file.
- **Auto-update now works**: v2 signs the `.msi` directly, producing `.msi.sig`; release assets are now `.msi` + `.msi.sig` + `-setup.exe` + a `latest.json` with real signature/URL (the v1 pipeline's signature format never matched `latest.json`, so updates could never land).
- **Frontend deps upgraded**: `@tauri-apps/api` / `@tauri-apps/cli` bumped to 2.x; `invoke` moved to `@tauri-apps/api/core`.
- **Fixed download progress**: progress events now report cumulative bytes (`downloaded`) instead of per-chunk increments, so the progress bar no longer jumps around.
- **CI release pipeline reworked**: signing-key normalization plus a fail-fast password check, aligned with cc-switch.

---

## Upgrading

- **Already on v0.1.0**: the built-in updater detects v0.2.0 on next launch and auto-installs (if **Settings → Startup → Auto-download and install updates** is enabled).
- **Fresh install**: grab the `.exe` or `.msi` from [Releases](https://github.com/gaoqiong001/dev-switch/releases).
